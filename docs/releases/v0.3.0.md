# v0.3.0 — multilingual Community and Classic streaming

Kroko STT Wyoming adds language-qualified model management while keeping the
Rust → sherpa-onnx OnlineRecognizer → Wyoming streaming architecture. One server
instance loads exactly one selected model, CPU-only and one thread by default.

- `LANGUAGE` plus `MODEL`/`KROKO_MODEL` is the model identity.
- New storage: `/models/<language>/<model>/`; no cross-language cache reuse.
- Pinned official Community downloads: German, English, Spanish, French, Italian,
  Hebrew, Dutch, Portuguese, Swedish and Turkish. Swedish offers Community-64 only.
- Community-128 remains the new-install default; Community-64 is optional.
- Only the selected missing model is downloaded, verified and atomically prepared.
- Valid local models are reused without downloading, including offline/read-only.
- Redundant free Community packages are removed only after verified preparation;
  components and installation records remain persistent. Manual Custom originals
  remain untouched. Invalid existing components are never automatically replaced.
- Local Custom packages and manifest-based prepared streaming Transducers are
  supported. No automatic public installer for third-party Custom models.
- Model-manager status, verification and scoped removal remain available.
- New application/container name: `kroko-stt-wyoming`; existing repository,
  GHCR package, template URL and Appdata defaults remain compatible.
- Unraid exposes the host port; internal port and listener retain fixed defaults.
- UID/GID 99:100 remains supported. Models are not included in Git or images.

## Upgrade

**Existing Classic installations continue to work. No automatic model migration
or replacement is performed. Community-128 is the default only for new/default
installations.**

Keep the existing model mount, `LANGUAGE=de` and explicit `KROKO_MODEL=classic`
selection. Flat Classic files, the named historical export directory, and German
v0.2.0 model folders remain recognized without moving or redownloading weights.
An ordinary image update retains saved container variables and mounts. Recreating
from a fresh template requires carrying over the old model selection explicitly.
New names do not rename existing containers or modify saved Unraid templates.

The old `:0.2.0` image and release remain unchanged. Use `ghcr.io/marco-taylor/kroko-stt-german-wyoming:0.3.0`; the existing
GHCR package name intentionally remains the update path. `latest` is mutable; explicit versions provide reproducible selection.

## Scope and licensing

The runtime remains sherpa-onnx; no additional inference runtime is shipped. Community license: **CC-BY-SA, upstream version unspecified**.
Model and code licenses are independent; Classic rights remain separately unresolved.
See [model management](../models.md), [licensing](../licensing.md) and
[local regression instructions](../development.md).

Available catalogue entries are not a claim of equal recognition accuracy across
languages. Native release acceptance focuses on German Classic, German Community-64
and Community-128, English Community-64 and Community-128, and supplied Custom models.
No new accuracy benchmark or change to historical benchmark results is implied.

## Validation

On Intel N100/Linux x86-64: 63 Rust test executions passed and the Docker build
succeeded. Isolated acceptance covered clean Community download, checksum and
atomic publication, restart without downloading, interrupted download, scoped
removal, Classic legacy layouts, the German v0.2.0 installation-record format,
Custom packages/manifests, DE/EN switching and offline/read-only operation.
German Classic/Community-64/Community-128 and English Community-64/Community-128
produced real Wyoming transcripts. Each tested instance initialized one recognizer.
German paced tests confirmed partial decoding before end-of-input for all three
Kroko profiles. Existing German Zipformer and Nemotron Custom regressions passed.
The image audit found no weights, audio, secrets or additional inference runtime.
