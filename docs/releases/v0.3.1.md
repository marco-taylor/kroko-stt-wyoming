# v0.3.1 — consistent multilingual project naming

The canonical project, GitHub repository, GHCR image and Unraid template are
`kroko-stt-wyoming`. This completes the naming transition; multilingual model
management was already present in v0.3.0. No recognition or decoding changes.

- New installs use the neutral Appdata directory and image name.
- Unraid hides the internal listener, container port and model-root variables;
  only the host port mapping and persistent model volume are exposed.
- Language and model remain a joint identity, stored under `/models/<language>/<model>`.
- Only the selected missing model is downloaded and only one recognizer is initialized.
  Switching language/model requires recreating the instance, releasing the old process.
- German Classic and legacy Community files remain usable without replacement,
  forced migration or unnecessary downloads. Keep existing model volume mounts.
- Prepared models work offline and read-only. Original Custom files are preserved.
- Community sources and SHA256 pins are unchanged. Weights are outside the image.
- UID/GID 99:100, streaming Wyoming and Home Assistant integration are unchanged.

Existing Classic installations continue to work. No automatic model migration or
replacement is performed. Community-128 is the default only for new/default installations.

The old template/icon filenames remain compatibility aliases. GitHub repository
redirects preserve old repository links. Previous versioned images/releases are
not overwritten. CA store ingestion is separate from publication of the template.

## Validation

On Intel N100: Docker build and 63 Rust test executions passed, plus six Unraid
contract tests. Isolated acceptance passed for Classic and German legacy layouts,
Community-64/128, DE/EN language switching, Custom models, restart without download,
offline/read-only use, scoped model removal and interrupted downloads. Paced audio
confirmed partial decoding before end-of-input. No ASR/model-manager source was changed.
